# PhasmaPlayer Android

This is the first Android host scaffold for `PhasmaPlayer`. It builds the normal engine CMake tree through Android Gradle Plugin, but only the lean runtime/player target set.

## Local Setup

1. Install Android Studio (or a JDK 17 — the committed Gradle wrapper pins Gradle 8.9), Android SDK CMake 3.22.1, NDK 28.2.13676358, and a full SDL2 source tree.
2. Copy `local.properties.example` to `local.properties`.
3. Set:
   - `sdk.dir` to the Android SDK path.
   - `sdl2Root` to a full SDL2 source checkout/release that contains `android-project/app/src/main/java/org/libsdl/app/SDLActivity.java`.
   - `spirvCrossRoot` to a full SPIRV-Cross source checkout/release with its CMake project.

The repository's current `PhasmaCore/third_party/SDL2` directory is header-only for this purpose; do not point `sdl2Root` at it.
The repository's current `PhasmaCore/third_party/spirv_cross` directory is also headers-only; Android needs the full source tree so CMake can build `spirv-cross-core` for the NDK.

## Build

From `PhasmaPlayer/android`, run the Gradle wrapper or open this directory in Android Studio:

```powershell
.\gradlew.bat :app:assembleDebug
```

On Linux/macOS use `./gradlew :app:assembleDebug`. The wrapper downloads its pinned Gradle 8.9 on first run, so no system Gradle install is required.

The Gradle build passes these first-mile engine switches to CMake:

- `PE_BUILD_EDITOR=OFF`
- `PE_BUILD_LAUNCHER=OFF`
- `PE_BUILD_MCP=OFF`
- `PE_WEBGPU=OFF`
- `PE_ENABLE_ASSIMP=OFF`
- `PE_ENABLE_RUNTIME_SHADER_COMPILER=OFF`
- `PE_PHYSICS=ON`
- `PE_AUDIO=OFF`

The app packages `PhasmaEditor/Assets` under APK `Assets/`, excluding the large model sample folders and `Scenes/**` so Android startup does not depend on local editor scene files. The startup scene and `editor_config.json` are shipped as **tracked** Android-local assets under `app/src/main/assets/Assets/` (`Scenes/android_physics_balls.pescene` + `editor_config.json` pointing at it). They live there — rather than relying on `PhasmaEditor/Assets/Scenes/*.pescene`, which `.gitignore` treats as user scenes — so a clean checkout produces a deterministic APK and does not bundle whatever local scene files happen to be on disk. The default Android scene is a primitive-only physics loop that drops 10 colorful balls into a box every five seconds, deletes the previous batch, and repeats. `PhasmaPlayerActivity` extracts the asset tree into app-private storage before SDL starts native code, matching the Android `Path::Assets` setup. The manifest and SDL orientation hint allow both portrait and landscape user orientations before window creation, while the renderer still presents unrotated frames through an identity swapchain transform and resizes render targets to the phone's current drawable extent. The Activity also reports system-bar/display-cutout insets to native code so the runtime UI can place HUD windows inside the visible safe area.

## Pre-baked shaders (required to render)

`PE_ENABLE_RUNTIME_SHADER_COMPILER=OFF` means the device has **no** shader compiler — the engine can only read precompiled SPIR-V from its on-disk cache. The APK therefore ships a pre-baked cache that the Activity extracts to `<internalStorage>/ShaderCache/` (the sibling of `Assets/` that `ShaderCache::Init` reads). Without it the first `Shader::Create` aborts.

Two engine properties make a desktop-baked cache resolve on-device:

- **Portable cache key.** The cache filename is a hash of the shader source + entry point + defines + SPIR-V target. That hash is computed with a deterministic FNV-1a (`PhasmaCore/Code/Base/Hash.h`), not `std::hash`, so the key is identical whether produced by the desktop MSVC build or the on-device NDK libc++ build.
- **Matched SPIR-V target.** Android hard-forces the SPIR-V target to Vulkan 1.2 (`RHI.cpp`). The bake host pins the same target via the `PHASMA_SPIRV_TARGET=1.2` env override so the keys *and* the emitted bytecode match.

The desktop bake host and the Android APK must be built from the **same engine revision** for the keys to match. To regenerate the cache after touching any shader, define, or the hash:

```powershell
# 1. Rebuild the desktop bake host with the current engine:
cmake --build build-ninja-full --config Release --target PhasmaPlayer
# 2. Bake (runs the player at vulkan1.2, harvests ShaderCache/_spv into prebaked/, and
#    asserts no blob requires shaderInt64 — the gate that keeps the Mali warn-on-Android safe):
pwsh tools/bake_android_shaders.ps1
# 3. Build the APK; gradle stages prebaked/ShaderCache/ into the APK automatically:
cd PhasmaPlayer/android ; .\gradlew.bat :app:assembleDebug
```

The baked blobs live in `PhasmaPlayer/android/prebaked/ShaderCache/_spv/` (git-ignored, regenerated by the script). When the APK `versionCode` changes, the Activity replaces the extracted shader cache so stale target-keyed blobs do not accumulate. Mali-class GPUs lack `shaderInt64`; the engine gates that feature softly on Android because no engine shader emits `OpCapability Int64` (the bake script verifies this), while `bufferDeviceAddress` stays hard-required.

## Cooked models (required for model scenes)

`PE_ENABLE_ASSIMP=OFF` means the device has **no** model importer — the player loads only the engine's cooked `.pemesh` format (vertex/index/aabb streams laid out exactly as they upload to the GPU). Assimp is editor-only and is used solely to import source models (glTF/FBX/OBJ) and cook them. So a scene that references a model file must reference a cooked `.pemesh`, and that `.pemesh` (plus the model's textures) must be staged into the APK.

Cooked assets are **build artifacts, not source** — they live in the git-ignored `prebaked/Models/` staging (never under `PhasmaEditor/Assets/`). Gradle bundles `prebaked/Models/<name>/` into the APK at `Assets/Models/<name>/`. To cook a model:

```powershell
# Rebuild the desktop cook host (it runs Assimp), then cook the model into prebaked/Models/<name>/
#  + copy its textures alongside (self-contained). The scene references ../Models/<name>/<name>.pemesh.
pwsh tools/cook_model.ps1 -Source PhasmaEditor/Assets/Objects/glTF-Sample-Models/Sponza/glTF/Sponza.gltf -Name Sponza -Build
# Then assemble; gradle stages prebaked/Models/ automatically:
cd PhasmaPlayer/android ; .\gradlew.bat :app:assembleDebug
```

Cooked model scenes can be added as Android-local scenes that reference `../Models/<name>/<name>.pemesh`; without the cook step those sources are skipped (file-not-found) and the model will not appear. Like the shader bake, the cook host and the engine must be the same revision (the `.pemesh` header carries a `sizeof(Vertex)` ABI guard that rejects a stale cooked file).
