# Engine, editor, and project assets

Asset content is split across three roots, each resolved by `Path` at startup:

- `Path::RuntimeAssets` — engine-required content the runtime cannot start without: render-pass shaders, `PassInfo/standard_pbr.pass`, default textures (`black`/`normal`/`white`/`ibl_brdf_lut`), the default particle texture, the splash screen, default global scripts (`fly_camera`, `editor_shortcuts`, `play_controls`), and runtime/tool fonts. Source lives at `Phasma/Runtime/RuntimeAssets/`; the build copies it next to the executable as `RuntimeAssets/`. The user never edits it.
- `Path::EditorAssets` — editor chrome (icons, fonts, profiler). Source at `Phasma/Editor/EditorAssets/`, copied next to the editor executable as `EditorAssets/`. Not shipped with the standalone player.
- `Path::Assets` — the active project's content (scenes, models, materials, sprites, prefabs, audio, user shaders). It is **not** copied into the build; it is the project assets root resolved from `phasma_settings.json` / `phasma_project.json`, and is where editor saves land.

Engine code loads fixed engine paths directly from `Path::RuntimeAssets`. Content a project may override (the splash screen, Lua-supplied shader/image/model/skybox paths, material-pass variant shaders) goes through `Path::ResolveAsset(relative)`, which checks the project assets root first and falls back to `Path::RuntimeAssets`. A project-local mirror of an engine shader therefore wins and must stay synchronized with engine-side compile contracts such as `GBUFFER_NO_VELOCITY`; otherwise the override can compile against the wrong MRT layout. While no carve has happened (`Assets == RuntimeAssets`) the resolver is a no-op, preserving legacy behavior.

The Android Gradle player is the packaged exception: its staging task copies the current engine runtime assets plus the configured game's complete `Assets/` file tree into the APK, with only explicit archival/host-entry exclusions. Do not whitelist only known top-level project folders; a new runtime folder such as `Data/` must ship without requiring another Gradle edit. Android lint and asset-merge tasks depend on that staging task. Before staging, Gradle verifies the content manifest written by `tools/bake_android_shaders.ps1` and rejects stale pre-baked SPIR-V; the bake script rebuilds its desktop player host before generating the cache. `PhasmaPlayerActivity` re-extracts the tree when the installed APK update time changes.

The build no longer copies project content. CMake copies only `RuntimeAssets/` and `EditorAssets/` (copy-on-change), creates an empty writable `Assets/` next to the executable as a fallback, and seeds a dev `phasma_settings.json` pinned to the sibling `PhasmaProjects/Sample` project only when none exists — so a rebuild never clobbers a user's chosen project or their saved scenes. Engine shaders and default scripts are watched for hot reload from `Path::RuntimeAssets`; the project's `Shaders`/`Scripts` are watched additionally when the project assets root differs from the runtime root.

`EditorAssets/Icons/pescene_icon.png` and `pemesh_icon.png` are the distinct FileBrowser icons for engine-authored scenes and cooked meshes. Each has a matching multi-resolution `.ico` for its Windows shell file type. Every desktop Phasma executable with an SDL window (Editor, Animator, Cook, Launcher, Player, and Profiler) applies `RuntimeAssets/Icons/phasma_icon.bmp` through the shared core window-icon helper on Windows and Linux; the matching Windows resource embeds a multi-resolution icon in each `.exe` for Explorer.
