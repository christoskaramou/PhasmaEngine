# Animation Timeline

A planar rig reduces the pose bar and every pose gizmo to XY Location, Z Rotation and XY Scale, projects Puppet Drag, two-bone IK, locks and pins onto the rig plane, and defaults the camera to Front Orthographic. The depth-assuming Generate Cycle, Body/Ballistic, contact and Balance tools are hidden in the UI and rejected by their agent actions, while Tween, Spring and Cycle remain available. `timeline.spline_ik` aims a selected spline chain at an XY target with a bend cap and sign, a stretch ceiling, per-joint bend influence and per-joint width scale, then keys the chain's complete TRS pose in one undo step.

PhasmaAnimator's `Animation Timeline` panel (`Phasma/Animator/Code/AnimationTimeline.*`) is the single rig-and-animation surface. Its always-visible **Rig** / **Animate** radio chooses the panel and viewport overlay without pausing playback, changing the clip or playhead, or displaying the rest pose; the action selector and transport/playhead remain shared so the **Rig** panel can scrub a posed mesh for Joint Blend. The **Animate** panel is a Blender-style animation editor over the selected model's `AnimationClip`s: a two-row header (Dope Sheet / Graph Editor mode, action selector with New / Duplicate / Rename / Delete, transport with jump-start, previous key, play reverse, play/pause, next key, jump-end, current frame, Start / End / FPS, auto-key, Snap, Loop, speed, Undo / Redo / Save), a channel region (Summary row plus one collapsible row per bone that expands into Location / Rotation / Scale sub-channels) and a frame ruler that owns scrubbing (the playhead line itself can also be dragged inside the key and curve areas; keys under the cursor take priority). Frames are derived from the clip data: frame-based clips map one tick to one frame, while assimp-cooked clips at 1000 ticks/s use the median key spacing as the frame grid, so a 15 fps mocap clip shows frames 0-300 and the FPS field edits playback rate without moving the grid. Keys are diamonds (white, orange when selected); a group or summary diamond stands for every key at that frame. Blender's interaction model applies: click / Shift-click / box select, tweak-drag or `G` to move (snapped to whole frames unless Ctrl), `S` to scale around the playhead, `X`/Delete, `Shift+D` duplicate, `Ctrl+C`/`Ctrl+V` paste at the playhead, `A` / `Alt+A`, `I` / `Alt+I` insert or delete keys on the selected bones at the current frame, `Home` frame all, `Space` / `Shift+Ctrl+Space` play forward / reverse, arrows step frames and jump between keys, `Ctrl+Z` / `Ctrl+Shift+Z` (and `Ctrl+Y`) local undo. Each TRS key owns the interpolation of its outgoing segment; both key-area context menus can set selected keys to Linear, Smooth cubic ease-in/out, or Stepped hold. Copy/paste preserves the mode, and a key inserted inside an existing segment inherits that segment's mode. View navigation follows Blender's view2d: wheel zooms around the cursor (the Graph Editor zooms both axes), Ctrl+wheel / Shift+wheel scroll, middle-drag pans, Ctrl+middle-drag zooms, `Numpad +` / `Numpad -` zoom the view centre, `Numpad .` frames the selected keys, the right-edge scrollbar scrolls the synchronized channel/key rows, and the bottom scroller's thumb pans while its end grips resize the visible range. The Graph Editor shows one F-curve per channel component (X red, Y green, Z blue, W yellow) for the selected bones with per-component visibility toggles, value dragging (quaternion components renormalize on write) and an optional Normalize view; its connectors show stepped jumps and sample eased or slerped segments to match runtime evaluation. Edits stay in the in-memory `ModelAsset` until `Save` writes the clips back through `ModelAssetCooked::WriteToFile` into the model's own `.pemesh`. A pose bar under the header is Blender's N-panel Transform for the active bone: Location / Rotation (XYZ Euler, degrees) / Scale relative to the bind pose at the current frame, and every edit keys that frame (there is no transient pose buffer), with `Key`, `Reset` (key the bind pose) and `Rest Pose` (show the bind pose: pauses playback and clears the evaluated joint matrices so skinning falls back to identity; nothing is keyed, and the next scrub, play or pose edit returns to the clip; while the rest display is active the playhead viewport pose - the Timeline pose overlay, gizmo, grabs and locks - reads the same rest transforms) buttons; a freshly baked model with no clips gets a first action automatically. Row, ruler, header, status and axis sizes are derived from the current font each frame (a scaled editor font never clips rows or labels), and a bone selected from the Rig Editor scrolls the channel list to its row. `AnimationEvaluator::SampleChannel` keeps the bind pose for channel components that have no keys (glTF/Blender semantics), so a hand-keyed rotation-only channel no longer collapses the bone onto its parent; `InsertKeyframe` samples through the same function. The `timeline.mode` / `timeline.frame` / `timeline.bone` / `timeline.save` / `timeline.clip` (select or create an action by name, set its end frame and fps) / `timeline.pose` (key one bone's loc / rot / scale relative to the bind pose at a frame; requests queue and land in one undo step) / `timeline.rest` (the Rest Pose button as an action) / `timeline.play` editor actions drive the same widget without mouse input, and `AnimationSystem` now wraps negative playback time so reverse playback loops. The window follows the hierarchy selection exactly like the Rig Editor: with nothing selected, or a selected model without a skeleton, it shows no target (there is no fallback to another skeleton in the scene). Selecting any node *inside* a character — one mesh part, or an empty bone node such as `CTRL_root` — drives the whole character: `AnimationRootOf` climbs from the selection to the highest ancestor whose animated nodes all belong to the selection's model and whose subtree holds no other model (a props group or the scene root is a boundary, so selecting a static prop beside a character never targets the character; a top-level empty such as a camera never climbs), and play / pause / scrub then reach every part instead of only the selected subtree. Queued `timeline.*` requests are dropped when the target vanishes or changes; a `timeline.frame` and a `timeline.pose` sent in one pump land at the requested frame, and lock re-solves key the frame the pose edit targeted (`PoseEditFrame`), not the playhead. Target resolution and the `timeline.*` request drains run every frame. Every agent action passes through `AnimatorApp::HandleAction`, which turns a mistyped argument (a number where a bool is expected) into an `{"error": ...}` reply instead of unwinding the editor host. Because clip channels reference bones by index, **Bake** drops any clips when the model's previous bone list is no longer a prefix of the baked one (old indices would read garbage bones and explode the pose); a re-bake, or one that only appends bones, keeps its clips; one that only removes trailing bones keeps them too and strips just the removed bones' channels; either outcome is reported in the bake status.

Timeline playback requires a selection that resolves to a rigged model (the animator selects the opened model's root). Selection loss or another character pause every unowned default-preview animation and clear its evaluated joints back to the bind pose; only the newly selected rig can retain playback. Switching the **Rig** / **Animate** radio does not rest the mesh, pause playback, change the clip, or move the playhead.

**Clip exchange and root motion.** `timeline.import {path, clip?}` uses the same importer as the File menu and appends uniquely named actions only after every requested action has retargeted successfully. Name-identical rigs keep their original keys and per-key interpolation; general name-based retargeting maps Location deltas between source and target bind bases without applying animated parent motion twice, preserves matching bone rotations, the shallowest animated Location carrier and authored scale, writes baked keys as Linear, and does not invent empty TRS curves. `timeline.export {path}` writes the active action as glTF. The Motion Doctor's **Root carrier** picker chooses any animated Location channel, **Include vertical** controls whether bounce is extracted, and **Extract Root Travel** removes horizontal travel by default so the action plays in place; `timeline.motion.root_extract {bone?, vertical?}` exposes the same operation. The viewport draws the extracted trajectory and Motion Doctor reports its loop delta. The extracted curve is an explicit `AnimationClip::rootMotion` track ignored by pose evaluation and serialized by cooked `.pemesh` v5 (the loader still accepts v3 Linear keys and v4 interpolation). Interval slide/scale, global frame remapping and Cycle keep that track synchronized; Cycle accumulates its travel into the repeated span. **Bake Root Travel** / `timeline.motion.root_bake` merges it into the Location curve again. Export bakes a temporary clip because glTF has no Phasma root-track field; it does not alter the action in memory and reports bake failure. Both operations are one undo step, and a rig bake that removes the carrier also drops its now-invalid root track.

**Pose clipboard, markers and layers.** The `Edit` menu carries Undo / Redo, **Copy Pose**, **Paste Pose** and **Paste Pose Flipped**. Over the viewport `Ctrl+C` / `Ctrl+V` copy and paste the pose (the selected bones, else the active bone, else every bone; `Ctrl+Shift+V` pastes it flipped onto the `.L` / `.R` twins by staging the paste in a scratch copy of the clip and running the mirror tool there) while the same keys over the dope sheet still copy and paste keys; a `PoseEntry` holds a bone's Loc / Rot / Scale relative to its bind pose by bone name, and a paste follows the pose bar's sequence (undo snapshot, key, lock re-solve, interval retween). Pasted keys find their bone in any action of the rig (`ClipboardEntry` carries the bone; the key clipboard survives a clip switch and dies with the model). `timeline.pose_copy {frame?, bones?}` and `timeline.pose_paste {frame?, flipped?}` are the actions. Ruler **markers** (`AnimationClip::markers`, cooked `.pemesh` v6, read by scripts through `animation.get_markers`) are added with `M` at the playhead or from the ruler's right-click menu, which also renames, jumps to and deletes the marker under the mouse; one marker per frame; `timeline.marker {op: list|add|remove|rename, frame?, name?, index?}`; they ride the clip's undo and Save. The Motion Doctor's **Layer** row bakes another action of the model onto the active one over the interval (or the whole action) for the selected bones, else every bone the source keys: a blend by weight, or an additive layer that applies the source's offset from its bind pose after the target's pose (a breathing or sway layer over a base); samples land on the frame grid and replace the span's keys with Linear ones, curves only for what the source keys, both clips sampled before anything is written (`AnimationClipTools::LayerClip`; `timeline.layer {clip, weight, additive, offset_frames, start_frame?, end_frame?, bones?, channels?}`). Bake Locks over the whole clip already lives in the pose viewport (`timeline.lock {op: bake}`).

**Pose library, generated gaits and the physics refinements.** The **Poses** button beside Motion Doctor opens the pose library: named `PoseEntry` sets shared by every model rigged from the same preset, stored in `<project>/RigPresets/Poses/<preset>.poses.json` (`custom` for a hand-made rig), saved from the current pose and applied - or applied flipped - at the playhead (double-click applies); `timeline.pose_library {op: list|save|apply|remove, name, frame?, flipped?, bones?, dir?}`, where `dir` points automation at a scratch directory. **Generate Cycle** writes a new looping walk or run action from the rig's bone names (`AnimationClipTools::GenerateGait`): thigh / shin / foot / toe, shoulder / upper arm / forearm / hand, hips / spine / chest / neck / head are found by the preset aliases (`thigh`, `*leg*`, `upper_arm`, `*arm*` ...) with a `.L` / `.R` (or `_L`, `.l`) side; legs and arms swing about the rig X axis as rig-space swings conjugated into each bone's bind frame, the pelvis sways and twists against the spine and head, the carrier (the hips role, else the skeleton root) bobs twice per cycle, and the travel goes to the root-motion track so the action plays in place. Feet slide - plant them with the contact tools or Balance afterwards; the presets' frame (+Y up, +Z forward, `.L` at +X) is assumed. `timeline.generate {gait: walk|run, frames?, amplitude?, stride?, root_motion?, name?}` reports the roles it matched and the stride. Balance's counter-lean is capped by the rig preset's `leanBudgetDegrees` (15 for the bipeds, 10 for the centaur and floating caster, 8 for the bird, 5 for the quadruped, none for a serpent, fish, arthropod or prop; `lean_budget_degrees` in a project preset file; `RigEditor::LeanBudgetDegrees`, reported by `rig.state`). The Body ballistic bake conserves angular momentum with the full inertia tensor: point masses plus every bone as a thin rod (`m l^2 / 12`) whose own turn rate counts, solved as `-J^-1 L`. An opened model is stood on the floor: the lowest point of its meshes goes to the ground plane, which moves only the scene node, so rig space - where every tool measures - is untouched. The animator previews root motion in place (`AnimationSystem::SetRootMotion(node, false)` on its states) and draws the trajectory instead.

The frame ruler also carries an **interval**: a span of frames the tools treat as one object (Cascadeur's interval edit). `Alt`-drag the ruler to mark one, drag its body to slide every key inside it, drag an edge to resize, `Shift`+edge to scale those keys from the far edge, and `Esc` or a click on the ruler outside the band to drop it. Slide and scale rebuild from the clip the drag started with, so dragging back and forth never compounds; a moved key overwrites the key it lands on (two moved keys stacked by the clip-range clamp keep the later source key), and the whole drag lands as one undo step that also restores the band. Both radios draw the frame ruler - the **Rig** panel scrubs a posed mesh for Joint Blend - so the band, its gestures and scrubbing are available on either side, and the interval is cleared only when the model or action changes. **Tween** on the pose bar bakes the frames strictly inside the interval for the selected bones, or every keyed bone when none are selected. A selected bone with no keys in the clip writes nothing and the status names it. `AnimationClipTools::TweenInterval` has two modes: `SampleClip` (the button and `timeline.tween`) keys what the clip already plays at each interior frame, so existing breakdowns survive and the interval's own ends are never written, while `RebuildFromEnds` (interval mode) pins both ends to the pose shown there, drops the interior and re-keys the span from that pair. Interior times sit on the clip's frame grid, so an unsnapped or agent-set fractional interval still keys whole frames. The baked keys are Linear, or Stepped where the sampled segment was stepped, because the samples already carry the easing - leaving them Smooth would make the evaluator ease an eased curve a second time. A channel with no keys of a kind is left alone, so tweening never invents a child Location curve that posing refused to create. With an interval set and the playhead strictly inside it, a user pose written at that frame (Puppet Drag / gizmo, the pose bar, `I` / dope-sheet insert through the shared `InsertKeyframe`, `timeline.pose`) becomes the new extreme and both halves are re-tweened from it in the same undo step; posing on an endpoint edits that extreme instead and re-tweens nothing. Batch writers pass `userPose = false` to `KeyViewportGlobalRotations` - Bake Locks keys every frame itself, so interval mode must not rebuild the in-betweens behind it. **Ballistic** beside it throws the root through the same interval instead of sliding it: `AnimationClipTools::BallisticInterval` keeps the horizontal path straight while rig Y follows gravity from the launch speed the two ends imply (`v0 = (y1 - y0)/T + gT/2`, so the arc lands exactly on the end value), pins both ends to what the curve already shows there and re-keys the interior Linear. The editable `g` (9.81 by default, in rig units per second squared) is the animator's exaggeration knob. It acts on the selected bone when that bone is a root or already owns a Location curve - mocap rigs keep translation on the hips under a keyless control root - and otherwise on the skeleton root; unlike Tween it *does* create the Location curve when there is none, because the arc is the curve being authored rather than an accidental constant, and an absent curve launches from `AnimationEvaluator::BindPose` - the evaluator's own empty-curve fallback, which removes the intermediate prefix - exactly as the clip would have played it. The button falls back to the skeleton root whenever the active bone carries no translation (an arm, a hand); `timeline.ballistic` instead refuses a `bone` it cannot bake, so a typo never retargets the arc. Posing that bone again inside the same interval rebuilds its curve from the ends like any other interval-mode edit, which flattens the arc, so bake it after the poses. With **Body** ticked the arc governs the body's centre of mass instead: `AnimationClipTools::BallisticBodyInterval` samples the source pose at every interior frame, weighs each bone's rest centre by the mass proxy the pose viewport derives (`AnimationPoseViewport::BodyMasses`: human segments take their share of Winter's body-mass table by bone name - forearm, upper_arm, hand, thigh, shin, foot, head, neck, and a trunk share split between every spine / chest / body / hips bone - scaled to the rig's own capsule volume, so a stubby cartoon arm still weighs what an arm weighs and a girth-fitted head capsule does not outweigh the trunk; a bone the table does not name is a thin capsule of its length, because an authored radius is a bind reach, not a girth; and a bone that owns a part adds the part's enclosed mesh volume at its centroid - the hand that carries the shovel weighs the shovel) and moves the root so the centre of mass, not the root, follows the arc between where it sits at the two ends, mapping that shift back into the root's key through its parent and prefix; only the mass under the moved bone counts, so a control root above the hips or a separate prop root is not part of the thrown body. Tucked limbs drop the hips and a heavy prop swung forward pulls the body after it; it is meant for airborne spans, since on the ground the feet move with the root. It carries angular momentum too: nothing in the air can turn the body but its own limbs, so the bake measures the momentum the poses carry about the centre of mass at every interior frame (point masses, central differences on the frame grid) and turns the root against it (`-L / I`, the body's inertia about that axis, integrated with the trapezoid rule), writing rotation keys on the root; the net turn over the flight is removed as a linear ramp so both ends keep their authored rotation, which means a swing that is uniform across the whole flight shows nothing, while a swing that starts and stops turns the body where it happens - the arm thrown forward in a jump tips the body back at that moment and the ramp brings it round by the landing. **Spring** beside it is follow-through: the selected bones root to tip (or one bone with its single-child descendants, so the root of a tail takes the whole tail) run through the damped spring chain `AnimationClipTools::BakeSecondarySpring` already simulates for the Motion Doctor, now over the interval alone - the chain starts on the source pose at the range start with no angular velocity of its own, samples land on the frame grid, the interior is re-keyed, both ends keep the source and every key outside the range stays (the hemisphere pass runs on into the rest of the curve so no sign flip is authored at the seams); a partial range cannot be Cyclic. Like Ballistic, bake it after the poses. **Balance** beside it is the grounded half of AutoPhysics (`AnimationPoseViewport::BakeBalance`): on every frame of the interval whose feet touch the ground - feet are the bones named foot / toe or holding a planted lock, and contact is read from the clip itself (a foot within 3% of the model height above the lowest foot in the span), never from the rest-anchor locks, which would pin the swing foot - the skeleton root (or the Location carrier, when the legs hang from it as on mocap hips) is shifted horizontally so the body's zero-moment point (from the same `BodyMasses` proxy; see below) stands over the convex hull of the feet in contact, and each contact foot is then bent back to where the frame had it with the two-bone solve (by its toe: a heel-first foot may slide its heel a little on a stiff leg), so a walk gains the hip sway over the stance foot nobody keys by hand; the two interval ends keep the position they showed (written explicitly, so a root the bake just gave a Location curve holds still outside the band), airborne interior frames take the shift interpolated from their grounded neighbours, the whole bake is one undo step, and its batch writes never retween. Contact is read at the same point auto contact plants (tail or heel), and the weight leaves a foot before the foot leaves the floor: the hull a frame's zero-moment point is held in holds only the feet still down through the next ~0.1 s (`lead_frames`, two at 24 fps), a foot is never added early, and a frame whose feet all leave inside that window - a push-off into flight - stands on the feet it has. The point held over the feet is the zero-moment point, `com - (h/g)·a`, with the centre of mass smoothed over about 0.1 s before it is differentiated (hand-keyed clips ripple, and `(h/g)·a` would turn a 1 cm key wobble into a decimetre of hip shove), the offset capped at half the centre's height, and the acceleration read from the source clip only - the shift's own acceleration is not fed back - so a body that stops short settles onto its heels and one that pushes off leads its feet instead of being shoved over them on every frame; `g` is the Ballistic knob. Re-planting the legs moves mass, so every frame takes a second, local root shift for what the re-plant moved the centre. Flight stays with Ballistic / Body. `timeline.balance_bake` (start_frame, end_frame; the marked interval by default) returns frames, airborne, outside_before, clamped, refused, max_shift, max_shift_delta, zmp_max, residual, frame_seconds, lead_frames and the carrier bone. **Cycle** beside Balance turns one stride into a walk: `AnimationClipTools::CycleInterval` pastes the interval's poses, mirrored across X with `.L` / `.R` swapped, onto the frames after it, replacing any keys already there (the action grows to twice the span; the seam keeps the stride's end pose, so the mirrored half starts one frame later; a cycle that writes nothing leaves the clip alone), offsets the Location carrier's keys in the new half so its travel continues where the stride left off (travel along X reverses in the mirror; the Motion Doctor's Stabilize World makes a treadmill afterwards), and closes the loop on the interval's start pose (rotation and scale) at the new end - a symmetric stride joins without a pop, an asymmetric one pops at the loop seam rather than inside the stride. `timeline.cycle` (start_frame, end_frame; the marked interval by default; two frames at least) returns keys_written and end_frame. `timeline.interval` (start / end frames; an end below start + 1 clears), `timeline.interval_slide` (delta_frames), `timeline.interval_scale` (factor, pivot_frame), `timeline.tween` (bones, every_n), `timeline.ballistic` (bone, gravity, body) and `timeline.motion.spring_bake` (bones, start_frame, end_frame and the spring knobs) drive the same state without mouse input.

### Coordinated posing and retiming

`timeline.info` reports the selected clip, available clip names, current/end frame, timeline FPS, duration in seconds, and exact marker times in frames and seconds. `timeline.clip_copy {source: name}` replaces the selected clip's complete animation data from another clip in the same model while retaining the target name. It copies keys, interpolation, markers, root motion, duration, and tick rate; source data remains intact. Invalid/self-copy requests fail. Undo/redo restores the prior clip and recalculates its frame grid. Use this before rebaking a derivative so shortened recovery cannot leave old target keys behind. Save edits before running an external offline bake.

`timeline.pose_state {bones?: [name, ...]}` reads the current evaluated Timeline pose in rig space. Each entry reports the bone name, head, tail, and XYZ Euler rotation in degrees; omitting `bones` returns the complete skeleton. It rejects unknown bones and queued frame/pose/clip requests, so callers should finish a frame change before reading or editing its pose.

`timeline.grab {bone, target?: [x,y,z], rotation?: [x,y,z]}` uses the viewport's existing position/orientation solver; at least one target is required. `target` addresses the bone tail in rig space and `rotation` is an absolute rig-space XYZ Euler orientation in degrees. Drive the hand when editing a held weapon: its attached weapon then retains the local grip transform. Directly grabbing a weapon bone still permits rotation inside the hand; this command does not add persistent grip constraints. Pins, locks, reach limits, balance, and undo continue to use the ordinary viewport path. Pose-library saves still follow the selected bones unless an explicit `bones` list is supplied; saving the complete ready pose must include attached props and clothing.

Timeline interval scaling/sliding now remaps clip markers in the edited span alongside curves and root motion. This applies to the shared UI/command retiming path, including marker-only changes, and participates in undo/save. Distinct markers that land on the same frame are retained. `timeline.layer` samples its source at the same elapsed time in seconds even when source and target clips use different tick rates (for example, imported milliseconds versus authored frame ticks). Its `offset_frames` is expressed in target timeline frames and converted to source ticks; shorter sources wrap, with an exact positive endpoint retaining the source end pose.
