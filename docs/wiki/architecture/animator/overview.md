# PhasmaAnimator

PhasmaAnimator is the animation program: its own executable (`Phasma/Animator/`, target `PhasmaAnimator`, option `PE_BUILD_ANIMATOR`), not a mode of PhasmaEditor. It is a plain host like PhasmaPlayer over `RuntimeSceneRenderer`: `main.cpp` boots SDL, the window (`PhasmaAnimator`) and the RHI through the runtime host primitives; `AnimatorApp` owns one `Scene` (a camera, a directional light, the grid and an optional ground shadow receiver; `ResetScene`), the runtime scene renderer, the same global systems the player creates (the runtime's scene hooks reach them), an ImGui context through the editor's shared plumbing (`GUI/Backends/GUIBackend`, `GUIState`, `GUI/Helpers.h`, `SelectionManager` - compiled in, never the editor GUI), and the `.pemesh` being animated. The whole window under the `File` menu is the `Animation Timeline` panel described below: its own viewport on top (the scene image with the pose overlay and the orbit camera: right-drag orbits, middle-drag pans, the wheel zooms, F frames the character; the camera projects at the region's aspect through `AnimatorApp::ViewportAspect`, so the region shows the whole render), the **Rig** / **Animate** editors under a drag bar. A newly opened character is framed on its own from slightly above. The drag bar resizes the two; the editors live in their own scrolling child (a plain wheel scrolls it, Ctrl+wheel stays zoom in the key / curve areas). `PhasmaLauncher` lists the program in its Run dropdown as `Phasma Animator`. The `Layout` menu carries the editor's `Style` themes (each with its font: Inter, Roboto, Open Sans, or ImGui's default for Classic), the `Font Size` steps (`io.FontGlobalScale` 0.85 / 1 / 1.25 / 1.5) and `Reset Layout` (viewport back to 60%); style and font scale persist in `animator_config.json` (`style`, `font_scale`) and the `layout.style {name}` / `layout.font_scale {scale}` actions set them. The `View` menu drives the orbit: Frame Character (F), Reset Camera, Front / Back / Right / Left / Top / Bottom, Orthographic, Grid, Ground, Axis Gizmo, Bone Names, Turntable and Maximize Viewport; named bookmarks and the last orbit per recent model are persisted. The viewport corner carries the editor's orientation gizmo (`GUI/OrientationGizmo.h`, shared with the editor Viewport). `timeline.view` takes `frame`, `reset`, `look [x,y,z]`, `ortho`, `grid`, `gizmo` and reports `orthographic` / `grid` / `gizmo`.

**Files and flow.** `File > Open .pemesh` (Ctrl+O; the native dialog on Windows, a `.pemesh` dropped on the window, or `--open <path>`) loads a cooked model: the previous scene goes (`Scene::NewScene`), the model is added, its root node selected, and the Timeline follows the selection as it always did. `File > Import Model` accepts glTF/GLB, FBX, DAE or OBJ, asks for the destination `.pemesh`, cooks it through the sibling `PhasmaCook` process without showing a console window, and opens the result; `animator.import_model {path, output?}` drives the same path and defaults the output beside the source. `File > Save` (and the Timeline's own Save / Ctrl+S) writes the clips back into the `.pemesh`; the Rig panel's Save / Bake write `<model>.rig.json` and `<model>_rigged.pemesh` beside it as before. `animator_config.json` beside the executable remembers the last model and the viewport share; the active project (`phasma_settings.json`) still decides `Path::Assets`, so project rig presets under `Assets/RigPresets` are available. There are no scenes, scripts, physics play, MCP server or hot reload in the animator.

Interactive Open, Recent, file drop, Exit and window-close routes ask to Save, Discard or Cancel when clip, rig-document or painted-weight state is dirty; the title carries `*` until every pending edit has been saved. File > Save and Ctrl+S save both the `.pemesh` and pending rig edits, using checked temporary writes and atomic replacement so a failed write cannot clear dirty state or truncate the last good file. `File > Import Clip` retargets BVH directly, another `.pemesh`, or a glTF/other model cooked through the sibling `PhasmaCook` executable onto the current skeleton by bone name; an import stages every source action before changing the current model, validates both skeleton hierarchies, and gives each external cook a private temporary directory with a two-minute timeout and full cleanup. `File > Export Active Clip` writes glTF 2.0 plus its `.bin`; mixed, Smooth or Stepped segment modes are sampled into faithful LINEAR output where glTF's sampler-wide interpolation cannot represent the source directly. The config also keeps eight recent files, visual toggles, camera bookmarks and the last camera for each recent model. Help > Hotkeys summarizes the authoring controls.

**Rendering.** The ImGui shell draws into the display target after the scene through `RuntimeSceneRenderer::SetOverlay` (a host overlay forces the blit path instead of direct-to-swapchain presentation); the overlay first copies the display target into the sampled image the viewport samples (`AnimatorApp::EnsureSceneTexture`, the same `GUIState::s_sceneViewImage` / `s_viewportTextureId` pair the editor's Viewport used), then records the ImGui pass. `RuntimeSceneRenderer::SetRuntimeSettingsForced(false)` keeps the grid on (the player forces editor overlays off every frame) and `ResetTAAHistory` is exposed for camera jumps. Animator starts at 100% render scale, but it is adjustable: a host overlay set before renderer initialization keeps the display and screenshot targets at window resolution while the scene targets scale, using the existing upsample/TAA path. `CreateFSSampledImage(false)` honors the unscaled size, so lower scene quality does not shrink or clip the interface. `TargetBounds` frames on the character's own column (the node translation) rather than the bone box, so a held tool never pulls the origin off centre.

**Settings menu.** `Settings > Rendering`, `Post Processing`, and `Environment & Camera` open a resizable, scrolling settings window (`AnimatorSettings.cpp`). Rendering and post-processing reuse the editor's `DrawSceneSettingsControls` and `DrawPostProcessControls`, compiled into Animator without the editor GUI. They expose supported present modes, render scale, render mode, dynamic rendering, lighting, shadows, fog, culling, LOD, debug overlays, time scale, IBL, SSAO, SSR, AA, sharpening, tonemapping, grading, bloom, depth of field and motion blur. Additional preview controls cover shadow map resolution/cascade count and LOD bias, normal/velocity precision, skybox selection or solid background, ground/grid, perspective/orthographic projection, FOV and clip planes. Present/render-mode events are handled before rendering; shadow-quality Apply waits for pending commands and resizes resources on the next frame (`ShadowPass::Resize` recreates changed shadow maps and uniforms before lighting descriptors refresh). Rendering preferences last for the current Animator session and survive opening another character; existing view/ground/grid config persistence is unchanged. The `animator.settings` command reports preview settings and target sizes, opens a tab with `tab: rendering|post_processing|environment`, toggles the window with `show`, and accepts validated render scale, present mode (the RHI display name), render mode, dynamic rendering, TAA/FXAA, motion blur strength/sample budget and shadow map/cascade changes. Resource and mode changes are deferred; query again after a frame for their effective values.

**Driving it without a mouse.** The animator has no MCP server; `AnimatorApp::PollCommandFile` polls `animator_command.json` beside the executable every frame (one `{"action","args"}` object or a list), runs the actions and writes `animator_result.json` (temp file + rename; an unreadable command file is left for the next frame). `animator.open {path}`, `animator.new`, `animator.screenshot {path}` (`RequestScreenshot`, the UI included), `animator.log {count, level}`, `animator.state`, `animator.exit`, plus every `timeline.*` and `rig.*` action the Timeline and Rig panel accept (`AnimatorApp::HandleAction` carries the routing the editor used to do: mode / frame / bone / save / play / undo / clip / pose / rest, the `rig.*` pose aliases). `tools/animator_client.py` speaks the old MCP probe vocabulary over that file so the timeline probes run unchanged.
