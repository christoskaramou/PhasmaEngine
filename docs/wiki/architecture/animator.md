# PhasmaAnimator

PhasmaAnimator is the animation program: its own executable (`Phasma/Animator/`, target `PhasmaAnimator`, option `PE_BUILD_ANIMATOR`), not a mode of PhasmaEditor. It is a plain host like PhasmaPlayer over `RuntimeSceneRenderer`: `main.cpp` boots SDL, the window (`PhasmaAnimator`) and the RHI through the runtime host primitives; `AnimatorApp` owns one `Scene` (a camera, a directional light and the grid; `ResetScene`), the runtime scene renderer, the same global systems the player creates (the runtime's scene hooks reach them), an ImGui context through the editor's shared plumbing (`GUI/Backends/GUIBackend`, `GUIState`, `GUI/Helpers.h`, `SelectionManager` - compiled in, never the editor GUI), and the `.pemesh` being animated. The whole window under the `File` menu is the `Animation Timeline` panel described below: its own viewport on top (the scene image with the pose overlay and the orbit camera: right-drag orbits, middle-drag pans, the wheel zooms, F frames the character; the camera projects at the region's aspect through `AnimatorApp::ViewportAspect`, so the region shows the whole render), the **Rig** / **Animate** editors under a drag bar. A newly opened character is framed on its own from slightly above. The drag bar resizes the two; the editors live in their own scrolling child (a plain wheel scrolls it, Ctrl+wheel stays zoom in the key / curve areas). `PhasmaLauncher` lists the program in its Run dropdown as `Phasma Animator`. The `Layout` menu carries the editor's `Style` themes (each with its font: Inter, Roboto, Open Sans, or ImGui's default for Classic), the `Font Size` steps (`io.FontGlobalScale` 0.85 / 1 / 1.25 / 1.5) and `Reset Layout` (viewport back to 60%); style and font scale persist in `animator_config.json` (`style`, `font_scale`) and the `layout.style {name}` / `layout.font_scale {scale}` actions set them. The `View` menu drives the orbit: Frame Character (F), Reset Camera (the front view from slightly above, framed), Front / Back / Right / Left / Top / Bottom, Orthographic (the orbit keeps its framing across the switch), Grid and Axis Gizmo; the viewport corner carries the editor's orientation gizmo (`GUI/OrientationGizmo.h`, shared with the editor Viewport - the arrows snap the orbit's look direction, and while an arrow is hovered the pose overlay draws with the mouse parked off-screen so its hit-gated clicks stay idle). `timeline.view` takes `frame`, `reset`, `look [x,y,z]`, `ortho`, `grid`, `gizmo` and reports `orthographic` / `grid` / `gizmo`.

**Files and flow.** `File > Open .pemesh` (Ctrl+O; the native dialog on Windows, a path field elsewhere), a `.pemesh` dropped on the window, or `--open <path>` load a cooked model: the previous scene goes (`Scene::NewScene`), the model is added, its root node selected, and the Timeline follows the selection as it always did. `File > Save` (and the Timeline's own Save / Ctrl+S) writes the clips back into the `.pemesh`; the Rig panel's Save / Bake write `<model>.rig.json` and `<model>_rigged.pemesh` beside it as before. `animator_config.json` beside the executable remembers the last model and the viewport share; the active project (`phasma_settings.json`) still decides `Path::Assets`, so project rig presets under `Assets/RigPresets` are available. There are no scenes, scripts, physics play, MCP server or hot reload in the animator.

**Rendering.** The ImGui shell draws into the display target after the scene through `RuntimeSceneRenderer::SetOverlay` (a host overlay forces the blit path instead of direct-to-swapchain presentation); the overlay first copies the display target into the sampled image the viewport samples (`AnimatorApp::EnsureSceneTexture`, the same `GUIState::s_sceneViewImage` / `s_viewportTextureId` pair the editor's Viewport used), then records the ImGui pass. `RuntimeSceneRenderer::SetRuntimeSettingsForced(false)` keeps the grid on (the player forces editor overlays off every frame) and `ResetTAAHistory` is exposed for camera jumps. `render_scale` is pinned to 1 in the animator: the overlay draws ImGui at window resolution into the display target, and a scaled target (the 0.75 default) clipped the UI and the viewport image at that scale, shifting the character off centre. `TargetBounds` frames on the character's own column (the node translation) rather than the bone box, so a held tool never pulls the origin off centre.

**Driving it without a mouse.** The animator has no MCP server; `AnimatorApp::PollCommandFile` polls `animator_command.json` beside the executable every frame (one `{"action","args"}` object or a list), runs the actions and writes `animator_result.json` (temp file + rename; an unreadable command file is left for the next frame). `animator.open {path}`, `animator.new`, `animator.screenshot {path}` (`RequestScreenshot`, the UI included), `animator.log {count, level}`, `animator.state`, `animator.exit`, plus every `timeline.*` and `rig.*` action the Timeline and Rig panel accept (`AnimatorApp::HandleAction` carries the routing the editor used to do: mode / frame / bone / save / play / undo / clip / pose / rest, the `rig.*` pose aliases). `tools/animator_client.py` speaks the old MCP probe vocabulary over that file so the timeline probes run unchanged.

## Animation Timeline

PhasmaAnimator's `Animation Timeline` panel (`Phasma/Animator/Code/AnimationTimeline.*`) is the single rig-and-animation surface. Its always-visible **Rig** / **Animate** radio chooses the panel and viewport overlay without pausing playback, changing the clip or playhead, or displaying the rest pose; the action selector and transport/playhead remain shared so the **Rig** panel can scrub a posed mesh for Joint Blend. The **Animate** panel is a Blender-style animation editor over the selected model's `AnimationClip`s: a two-row header (Dope Sheet / Graph Editor mode, action selector with New / Duplicate / Rename / Delete, transport with jump-start, previous key, play reverse, play/pause, next key, jump-end, current frame, Start / End / FPS, auto-key, Snap, Loop, speed, Undo / Redo / Save), a channel region (Summary row plus one collapsible row per bone that expands into Location / Rotation / Scale sub-channels) and a frame ruler that owns scrubbing (the playhead line itself can also be dragged inside the key and curve areas; keys under the cursor take priority). Frames are derived from the clip data: frame-based clips map one tick to one frame, while assimp-cooked clips at 1000 ticks/s use the median key spacing as the frame grid, so a 15 fps mocap clip shows frames 0-300 and the FPS field edits playback rate without moving the grid. Keys are diamonds (white, orange when selected); a group or summary diamond stands for every key at that frame. Blender's interaction model applies: click / Shift-click / box select, tweak-drag or `G` to move (snapped to whole frames unless Ctrl), `S` to scale around the playhead, `X`/Delete, `Shift+D` duplicate, `Ctrl+C`/`Ctrl+V` paste at the playhead, `A` / `Alt+A`, `I` / `Alt+I` insert or delete keys on the selected bones at the current frame, `Home` frame all, `Space` / `Shift+Ctrl+Space` play forward / reverse, arrows step frames and jump between keys, `Ctrl+Z` / `Ctrl+Shift+Z` (and `Ctrl+Y`) local undo. Each TRS key owns the interpolation of its outgoing segment; both key-area context menus can set selected keys to Linear, Smooth cubic ease-in/out, or Stepped hold. Copy/paste preserves the mode, and a key inserted inside an existing segment inherits that segment's mode. View navigation follows Blender's view2d: wheel zooms around the cursor (the Graph Editor zooms both axes), Ctrl+wheel / Shift+wheel scroll, middle-drag pans, Ctrl+middle-drag zooms, `Numpad +` / `Numpad -` zoom the view centre, `Numpad .` frames the selected keys, the right-edge scrollbar scrolls the synchronized channel/key rows, and the bottom scroller's thumb pans while its end grips resize the visible range. The Graph Editor shows one F-curve per channel component (X red, Y green, Z blue, W yellow) for the selected bones with per-component visibility toggles, value dragging (quaternion components renormalize on write) and an optional Normalize view; its connectors show stepped jumps and sample eased or slerped segments to match runtime evaluation. Edits stay in the in-memory `ModelAsset` until `Save` writes the clips back through `ModelAssetCooked::WriteToFile` into the model's own `.pemesh`. A pose bar under the header is Blender's N-panel Transform for the active bone: Location / Rotation (XYZ Euler, degrees) / Scale relative to the bind pose at the current frame, and every edit keys that frame (there is no transient pose buffer), with `Key`, `Reset` (key the bind pose) and `Rest Pose` (show the bind pose: pauses playback and clears the evaluated joint matrices so skinning falls back to identity; nothing is keyed, and the next scrub, play or pose edit returns to the clip; while the rest display is active the playhead viewport pose - the Timeline pose overlay, gizmo, grabs and locks - reads the same rest transforms) buttons; a freshly baked model with no clips gets a first action automatically. Row, ruler, header, status and axis sizes are derived from the current font each frame (a scaled editor font never clips rows or labels), and a bone selected from the Rig Editor scrolls the channel list to its row. `AnimationEvaluator::SampleChannel` keeps the bind pose for channel components that have no keys (glTF/Blender semantics), so a hand-keyed rotation-only channel no longer collapses the bone onto its parent; `InsertKeyframe` samples through the same function. The `timeline.mode` / `timeline.frame` / `timeline.bone` / `timeline.save` / `timeline.clip` (select or create an action by name, set its end frame and fps) / `timeline.pose` (key one bone's loc / rot / scale relative to the bind pose at a frame; requests queue and land in one undo step) / `timeline.rest` (the Rest Pose button as an action) / `timeline.play` editor actions drive the same widget without mouse input, and `AnimationSystem` now wraps negative playback time so reverse playback loops. The window follows the hierarchy selection exactly like the Rig Editor: with nothing selected, or a selected model without a skeleton, it shows no target (there is no fallback to another skeleton in the scene). Selecting any node *inside* a character — one mesh part, or an empty bone node such as `CTRL_root` — drives the whole character: `AnimationRootOf` climbs from the selection to the highest ancestor whose animated nodes all belong to the selection's model and whose subtree holds no other model (a props group or the scene root is a boundary, so selecting a static prop beside a character never targets the character; a top-level empty such as a camera never climbs), and play / pause / scrub then reach every part instead of only the selected subtree. Queued `timeline.*` requests are dropped when the target vanishes or changes; a `timeline.frame` and a `timeline.pose` sent in one pump land at the requested frame, and lock re-solves key the frame the pose edit targeted (`PoseEditFrame`), not the playhead. Target resolution and the `timeline.*` request drains run every frame. Every agent action passes through `AnimatorApp::HandleAction`, which turns a mistyped argument (a number where a bool is expected) into an `{"error": ...}` reply instead of unwinding the editor host. Because clip channels reference bones by index, **Bake** drops any clips when the model's previous bone list is no longer a prefix of the baked one (old indices would read garbage bones and explode the pose); a re-bake, or one that only appends bones, keeps its clips; one that only removes trailing bones keeps them too and strips just the removed bones' channels; either outcome is reported in the bake status.

Timeline playback requires a selection that resolves to a rigged model (the animator selects the opened model's root). Selection loss or another character pause every unowned default-preview animation and clear its evaluated joints back to the bind pose; only the newly selected rig can retain playback. Switching the **Rig** / **Animate** radio does not rest the mesh, pause playback, change the clip, or move the playhead.

The frame ruler also carries an **interval**: a span of frames the tools treat as one object (Cascadeur's interval edit). `Alt`-drag the ruler to mark one, drag its body to slide every key inside it, drag an edge to resize, `Shift`+edge to scale those keys from the far edge, and `Esc` or a click on the ruler outside the band to drop it. Slide and scale rebuild from the clip the drag started with, so dragging back and forth never compounds; a moved key overwrites the key it lands on (two moved keys stacked by the clip-range clamp keep the later source key), and the whole drag lands as one undo step that also restores the band. Both radios draw the frame ruler - the **Rig** panel scrubs a posed mesh for Joint Blend - so the band, its gestures and scrubbing are available on either side, and the interval is cleared only when the model or action changes. **Tween** on the pose bar bakes the frames strictly inside the interval for the selected bones, or every keyed bone when none are selected. A selected bone with no keys in the clip writes nothing and the status names it. `AnimationClipTools::TweenInterval` has two modes: `SampleClip` (the button and `timeline.tween`) keys what the clip already plays at each interior frame, so existing breakdowns survive and the interval's own ends are never written, while `RebuildFromEnds` (interval mode) pins both ends to the pose shown there, drops the interior and re-keys the span from that pair. Interior times sit on the clip's frame grid, so an unsnapped or agent-set fractional interval still keys whole frames. The baked keys are Linear, or Stepped where the sampled segment was stepped, because the samples already carry the easing - leaving them Smooth would make the evaluator ease an eased curve a second time. A channel with no keys of a kind is left alone, so tweening never invents a child Location curve that posing refused to create. With an interval set and the playhead strictly inside it, a user pose written at that frame (Puppet Drag / gizmo, the pose bar, `I` / dope-sheet insert through the shared `InsertKeyframe`, `timeline.pose`) becomes the new extreme and both halves are re-tweened from it in the same undo step; posing on an endpoint edits that extreme instead and re-tweens nothing. Batch writers pass `userPose = false` to `KeyViewportGlobalRotations` - Bake Locks keys every frame itself, so interval mode must not rebuild the in-betweens behind it. **Ballistic** beside it throws the root through the same interval instead of sliding it: `AnimationClipTools::BallisticInterval` keeps the horizontal path straight while rig Y follows gravity from the launch speed the two ends imply (`v0 = (y1 - y0)/T + gT/2`, so the arc lands exactly on the end value), pins both ends to what the curve already shows there and re-keys the interior Linear. The editable `g` (9.81 by default, in rig units per second squared) is the animator's exaggeration knob. It acts on the selected bone when that bone is a root or already owns a Location curve - mocap rigs keep translation on the hips under a keyless control root - and otherwise on the skeleton root; unlike Tween it *does* create the Location curve when there is none, because the arc is the curve being authored rather than an accidental constant, and an absent curve launches from `AnimationEvaluator::BindPose` - the evaluator's own empty-curve fallback, which removes the intermediate prefix - exactly as the clip would have played it. The button falls back to the skeleton root whenever the active bone carries no translation (an arm, a hand); `timeline.ballistic` instead refuses a `bone` it cannot bake, so a typo never retargets the arc. Posing that bone again inside the same interval rebuilds its curve from the ends like any other interval-mode edit, which flattens the arc, so bake it after the poses. With **Body** ticked the arc governs the body's centre of mass instead: `AnimationClipTools::BallisticBodyInterval` samples the source pose at every interior frame, weighs each bone's rest centre by the mass proxy the pose viewport derives (`AnimationPoseViewport::BodyMasses`: human segments take their share of Winter's body-mass table by bone name - forearm, upper_arm, hand, thigh, shin, foot, head, neck, and a trunk share split between every spine / chest / body / hips bone - scaled to the rig's own capsule volume, so a stubby cartoon arm still weighs what an arm weighs and a girth-fitted head capsule does not outweigh the trunk; a bone the table does not name is a thin capsule of its length, because an authored radius is a bind reach, not a girth; and a bone that owns a part adds the part's enclosed mesh volume at its centroid - the hand that carries the shovel weighs the shovel) and moves the root so the centre of mass, not the root, follows the arc between where it sits at the two ends, mapping that shift back into the root's key through its parent and prefix; only the mass under the moved bone counts, so a control root above the hips or a separate prop root is not part of the thrown body. Tucked limbs drop the hips and a heavy prop swung forward pulls the body after it; it is meant for airborne spans, since on the ground the feet move with the root. It carries angular momentum too: nothing in the air can turn the body but its own limbs, so the bake measures the momentum the poses carry about the centre of mass at every interior frame (point masses, central differences on the frame grid) and turns the root against it (`-L / I`, the body's inertia about that axis, integrated with the trapezoid rule), writing rotation keys on the root; the net turn over the flight is removed as a linear ramp so both ends keep their authored rotation, which means a swing that is uniform across the whole flight shows nothing, while a swing that starts and stops turns the body where it happens - the arm thrown forward in a jump tips the body back at that moment and the ramp brings it round by the landing. **Spring** beside it is follow-through: the selected bones root to tip (or one bone with its single-child descendants, so the root of a tail takes the whole tail) run through the damped spring chain `AnimationClipTools::BakeSecondarySpring` already simulates for the Motion Doctor, now over the interval alone - the chain starts on the source pose at the range start with no angular velocity of its own, samples land on the frame grid, the interior is re-keyed, both ends keep the source and every key outside the range stays (the hemisphere pass runs on into the rest of the curve so no sign flip is authored at the seams); a partial range cannot be Cyclic. Like Ballistic, bake it after the poses. **Balance** beside it is the grounded half of AutoPhysics (`AnimationPoseViewport::BakeBalance`): on every frame of the interval whose feet touch the ground - feet are the bones named foot / toe or holding a planted lock, and contact is read from the clip itself (a foot within 3% of the model height above the lowest foot in the span), never from the rest-anchor locks, which would pin the swing foot - the skeleton root (or the Location carrier, when the legs hang from it as on mocap hips) is shifted horizontally so the body's zero-moment point (from the same `BodyMasses` proxy; see below) stands over the convex hull of the feet in contact, and each contact foot is then bent back to where the frame had it with the two-bone solve (by its toe: a heel-first foot may slide its heel a little on a stiff leg), so a walk gains the hip sway over the stance foot nobody keys by hand; the two interval ends keep the position they showed (written explicitly, so a root the bake just gave a Location curve holds still outside the band), airborne interior frames take the shift interpolated from their grounded neighbours, the whole bake is one undo step, and its batch writes never retween. Contact is read at the same point auto contact plants (tail or heel), and the weight leaves a foot before the foot leaves the floor: the hull a frame's zero-moment point is held in holds only the feet still down through the next ~0.1 s (`lead_frames`, two at 24 fps), a foot is never added early, and a frame whose feet all leave inside that window - a push-off into flight - stands on the feet it has. The point held over the feet is the zero-moment point, `com - (h/g)·a`, with the centre of mass smoothed over about 0.1 s before it is differentiated (hand-keyed clips ripple, and `(h/g)·a` would turn a 1 cm key wobble into a decimetre of hip shove), the offset capped at half the centre's height, and the acceleration read from the source clip only - the shift's own acceleration is not fed back - so a body that stops short settles onto its heels and one that pushes off leads its feet instead of being shoved over them on every frame; `g` is the Ballistic knob. Re-planting the legs moves mass, so every frame takes a second, local root shift for what the re-plant moved the centre. Flight stays with Ballistic / Body. `timeline.balance_bake` (start_frame, end_frame; the marked interval by default) returns frames, airborne, outside_before, clamped, refused, max_shift, max_shift_delta, zmp_max, residual, frame_seconds, lead_frames and the carrier bone. **Cycle** beside Balance turns one stride into a walk: `AnimationClipTools::CycleInterval` pastes the interval's poses, mirrored across X with `.L` / `.R` swapped, onto the frames after it, replacing any keys already there (the action grows to twice the span; the seam keeps the stride's end pose, so the mirrored half starts one frame later; a cycle that writes nothing leaves the clip alone), offsets the Location carrier's keys in the new half so its travel continues where the stride left off (travel along X reverses in the mirror; the Motion Doctor's Stabilize World makes a treadmill afterwards), and closes the loop on the interval's start pose (rotation and scale) at the new end - a symmetric stride joins without a pop, an asymmetric one pops at the loop seam rather than inside the stride. `timeline.cycle` (start_frame, end_frame; the marked interval by default; two frames at least) returns keys_written and end_frame. `timeline.interval` (start / end frames; an end below start + 1 clears), `timeline.interval_slide` (delta_frames), `timeline.interval_scale` (factor, pivot_frame), `timeline.tween` (bones, every_n), `timeline.ballistic` (bone, gravity, body) and `timeline.motion.spring_bake` (bones, start_frame, end_frame and the spring knobs) drive the same state without mouse input.

## Rig Panel

The `Animation Timeline` panel's **Rig** panel, implemented by `Phasma/Animator/Code/RigEditor.*`, authors a skeleton plus a per-bone influence shape over the selected model: select any node of a loaded `.pemesh` and the widget resolves the model root, loads `<model>.rig.json` from beside the `.pemesh` when one exists, otherwise imports the model's existing skeleton, otherwise starts empty; deselecting (or selecting a node of no model) drops the target again — the document is autosaved first and undo/redo stay keyed to the rig file, so re-selecting brings both back. Bones are head/tail segments in rig space (the model root node's local frame; shell node transforms are folded in) with a capsule shape (a radius at each end) and a `rigid` flag (vertices inside belong to that bone only, for parts-style characters). Bones come from *Load Existing* (skeleton import) or the **Preset** menu: *Auto from Shells* (one bone per mesh shell along its principal axis, hierarchy from a spanning tree grown from the largest shell by bounds gap and normalised overlap, joint at the contact point, rigid weights), the built-in templates (`RigPresetLibrary::BuiltIn`: *Humanoid*, *Biped + Tail*, *Quadruped*, *Centaur*, *Bird*, *Insect* / *Spider* with three / four fanned leg pairs, *Serpent*, *Fish*, *Floating Caster* and the *Prop* rigs Hinge / Chest / Flag / Pendulum / Bounce — Blender-style names, `.L` written once and mirrored, shell globs with a `{s}` side placeholder) and every project preset from `Assets/RigPresets`, applied on selection — the menu shows the preset the bones came from, or *Custom* once they have been hand-edited. A preset attaches to the mesh in three layers: shell globs claim parts by name (a claimed part is owned 100%); every joint is then dropped to the middle of the mesh along Z with the drag handles' Volume snap and its capsule radius capped at the limb's half-thickness — an open or flat mesh such as an alpha cutout puts the joint on its surface and keeps the radius (joints outside the mesh keep the bounds fit; the status line counts both); and presets carrying template landmarks (the humanoid layouts) first measure the mesh — Y slices split into X blobs, the blob nearest the centre line standing in for the torso — for the crotch (first one-blob slice above a run of two-blob leg slices), shoulders (widest torso slice) and neck (narrowest slice above them), remapping the template's Y stations piecewise onto them and its hip / shoulder half-widths onto the measured ones; any landmark that cannot be found falls back to a proportion and is named in the status line. **Rig Transform** above the bone properties moves, rotates and scales every bone at once about an editable rig-space XYZ pivot (radii follow the average scale), whose **Reset** button returns it to the origin; the transform fields are deltas from the drag's start, one undo step, and reset when the drag ends; `rig.transform {move, rotate, scale, pivot}` accepts the same `pivot[3]` in one shot; *Add Bone* / *Extrude Child* / drag-drop reparenting / rename / delete cover the manual path. The viewport draws every bone (rigid bones tinted red, the selection yellow and noticeably thicker) with its capsule outline, skinned to the Animation Timeline pose so capsules sit on the posed mesh (Rest Pose or no resolved pose keeps bind); joints, the bone's midpoint (moves the whole bone) and the selected bone's radius squares are ImGui handles dragged incrementally in the camera-facing plane, with Blender's armature modifiers: hold `X` / `Y` / `Z` to lock the move to a rig axis (a guide line is drawn), `Shift` for precision (0.1x), `Ctrl` to invert the toolbar **Snap** magnet whose modes are *Joints* (other bones' heads and tails within 24 px of the cursor — only visible dots, never hidden shell points; the joint keeps following the free cursor position, so it releases cleanly when the cursor leaves the radius, and the selected bone's handles take priority where joints coincide so a snapped head stays grabbable), *Surface* (mesh under the cursor), *Volume* (halfway through the mesh under the cursor, Blender's Volume snap; the default) and *Increment* (0.01 grid); a connected child's head follows its parent's tail, and *Connect to Parent* in the bone properties puts a head exactly on its parent's tail without any mouse precision (Blender's Connect). **Mirror X** is Blender's X-Axis Mirror: every edit of a bone named `*.L`/`*.R` (`_L`/`_R`, `.l`/`.r`) is mirrored to its twin across the rig's X plane, and while it is on *Add Bone* / *Extrude Child* / `rig.add` create the bone as a `.L`/`.R` pair (side from the head's X, the twin under the parent's twin); bones without a side suffix are not mirrored. The **Heat** combo paints the weights the capsules would bake onto the mesh through the GBuffer's per-vertex colour (base colour x vertex colour): *Selected* fades grey to orange by the selected bone's weight, *All* blends every bone's colour (the same colours the overlay then uses); the original vertex colours are restored on *Off*. Weights come from `ComputeVertexWeights`: a bone can own a part outright (the **Shell** combo in the bone properties; *Auto from Shells* binds every bone to its shell, `"shell"` in `rig.json` and in `rig.add` / `rig.set`) and every vertex of that mesh then follows it fully — a capsule cannot match a pre-cut torso or boot, and depth-based tie-breaks always hand a shell's surface vertices to a fatter neighbouring capsule, which is why the shapes alone gave wrong weights on parts characters; for unowned meshes a rigid capsule claims the vertices inside it, then — with the toolbar's **Geodesic** checkbox on (the default; `"geodesic"` in `rig.json`) — the surface-aware bind in `Phasma/Animator/Code/Animation/GeodesicBind.*` decides: coincident vertices are welded so distance can cross UV seams, each bone seeds the surface its capsule sits inside (rays cast around the bone axis that leave the mesh within 1.25 radii, so a control bone in the air or a capsule thinner than the limb seeds nothing and gets no region — the bake status names such bones), distance then travels along the mesh from those seeds and the nearest bone labels each vertex (a hand resting against a hip stays a hand, a cloth hem stays with the leg it hangs from, because the way round over the surface is long even when the straight line is short); only bones within two hierarchy steps (parent, grandparent, child, grandchild, sibling) blend across a seam, in a smoothstep band as wide as 1.5 radii of the thinner bone capped at 35% of the shorter bone (girth-fitted torso capsules would otherwise smear the whole chest), a rigid label never blends but does bleed into its soft neighbour's band, a spline-link label takes the chain weights, and two relaxation passes even out the seed lattice; a mesh island no bone's surface reaches (or the checkbox off) falls back to the capsule rule: soft capsules blend with a smooth falloff and normalise to at most four influences, and vertices outside every capsule follow the nearest one — the bake will write exactly these. The table is rebuilt at bake and at each heat refresh (about 0.4 s on a 30k-vertex hero), never per frame. Files saved before shell bindings existed are migrated on load by binding each bone to the shell of the same name. A bone that owns a part draws no shape and has its radii / Rigid fields locked (the shape decides nothing for it); its head and tail stay editable because they are the part's pivot and axis at bake. Every mutation (presets, add / remove / reparent / rename, property edits, viewport drags, actions) pushes a whole-document snapshot onto a 64-deep local undo stack: `Ctrl+Z` / `Ctrl+Shift+Z` (or `Ctrl+Y`) while the window is focused, or the Undo / Redo toolbar buttons; the stacks belong to the rig file, so they survive scene reloads, play/stop and re-imports of the same `.pemesh` and only reset when another model is targeted. The document is `<model>.rig.json` beside the `.pemesh`: the widget autosaves it after every edit (once no drag or field is active) and reloads it whenever the model is re-resolved, so editor restarts and scene reloads keep the rig; `Save rig.json` forces a write. Because scene loads and snapshot restores rebuild nodes without registering model roots, target resolution falls back to the model found in the selected node's subtree and the highest ancestor that carries no other model's meshes. The file is also the export contract for Blender/MoCapAnything. The `rig.state` / `rig.preset` / `rig.add` / `rig.set` / `rig.remove` / `rig.select` / `rig.save` / `rig.load` / `rig.shapes` / `rig.snap` / `rig.mirror` / `rig.heat` / `rig.undo` / `rig.redo` editor actions (`rig.state` also lists the model's shells with centroid, axis endpoints and radius) drive the same widget without mouse input. **Bake** (`rig.bake`) writes the rig into the mesh: every part is flattened into rig space (its node local becomes identity, normals/tangents transformed, bounds recomputed), the skeleton is built from the bones with translation-only bind frames (`localBindTransform = translate(head - parentHead)`, `offsetMatrix = inverse(translate(head))`, identity `intermediatePrefix`/`rootTransform`, so the bind pose skins to identity), `ComputeVertexWeights` fills joints/weights in both the PBR and the depth/shadow vertex streams (indexed by `vertexOffset`), every mesh is flagged skinned, and the result is saved as `<model>_rigged.pemesh` beside the source with the rig.json copied to `<model>_rigged.rig.json`; the scene then swaps the source model for the rigged one and selects its root (any scene-level transform of the old root is not carried over). Verified on the Farmer shells: the baked render is pixel-identical to the source and all 48,923 vertices bind 100% to their own part's bone. **Spline chains** are the strip rig's smooth deformation inside the same document: *Spline Chain* (toolbar, or `rig.chain {bone, count}`) subdivides the selected bone into `count` connected links flagged `spline` (Mirror X converts the twin too; the bone's children move to the last link; the per-bone *Spline* checkbox flags links by hand), the viewport draws the chain's Catmull-Rom curve in green, and any vertex a spline link claims (by owned part, rigid capsule or strongest soft capsule) is weighted like `skinned_strip_2d`: the closest point on the chain polyline (link heads plus the last tail) picks the segment, and the four surrounding joints get the Catmull-Rom station basis — including its negative outer lobes, which Bake now keeps — so a tail, cape, rope or shovel handle bends as one smooth curve under plain FK rotation keys. Joint frames stay the FK rotations (no 3D tangent-frame smoothing yet; the chain also claims its vertices outright rather than blending into the body at the root). Bake swaps the model by deleting the rig root's subtree, then `Scene::RemoveModel` (which now also drops any node still drawing a model that a scene load registered without root nodes, instead of leaving them pointing at the deleted asset), and re-applies the old root's local matrix to the rigged root. Baked rest frames are bone-aligned like Blender's: Y runs head → tail, X is the rig X projected perpendicular to the bone (so an upright leg keeps its rig-space forward/back meaning), Z = X × Y; `localBindTransform = inverse(parentRest) * rest`, `offsetMatrix = inverse(rest)`, so the bind pose still skins to identity while the Timeline's pose Rot / Loc (and `timeline.pose`) act in the bone's own frame — Rot Y twists along the bone, X / Z bend it, Loc slides along it. Selecting a bone in the Rig Editor (viewport handle or tree) also makes it the Animation Timeline's active bone, so the pose bar edits the bone under the cursor.

The **Rig** panel owns bind authoring and weights only. The selected bone's properties author the Puppet Pin, bind-frame swing/twist limits (zero means unrestricted), and a fixed Rest Lock at the authored tail; presets may supply the same `pins`, `locks`, and per-bone `limit` data. Capsules, rigid/shell/spline binding, heat visualization, Bake, and Joint Blend remain on this surface. Joint Blend uses the selected bind bone and the Animation Timeline's evaluated pose (or the bind rest pose when no Timeline pose is resolved), paints Add/Erase/Smooth weights, keeps its 16-deep weight undo, and only persists through Save Weights or `rig.weight_save`. Enabling it does not change bone selection: Add / Erase / Smooth, Radius, Strength and Save Weights sit indented under the checkbox and hide again when it is off; pick a bind bone in the tree to paint.

Viewport posing is owned by `AnimationPoseViewport.{h,cpp}` inside the **Animate** panel. Its compact controls sit beside the existing pose bar and reuse the Timeline channel selection instead of adding another bone tree or duplicate Auto Key/pose-undo controls. Onion Bones, Motion Trail, Two-Bone IK, the reference-sequence UI/cache/overlay, pose picking, pins and pose-lock use all live there. The gizmo stays at the selected tail with the bone's rig-global orientation; Rotate / Move / Both remain handle filters on Puppet Drag, and tail-dot drag is the same move-only solve. Child edits recruit the limited chain and key rig-global rotations through one `KeyViewportGlobalRotations` batch, never child Location keys; Rotate holds the tail, root translation retains the direct Timeline path, and Mirror X solves both counterpart chains in the same undo step. CCD stiffness remains 1 for the selected bone and parent, 0.35 for the grandparent and 0.2 farther up, stopping before the first pin/root; authored swing/twist cones clamp against the bind channel frame around local +Y. Locks still solve the bone and parent with `SolveTwoBoneIk`, preserve bend direction through straight limbs, skip both dragged counterpart chains, and reapply on release or after pose-bar/`timeline.pose` edits. **Hold Posed** (on by default, beside Add Lock) makes that automatic in Cascadeur's sense: releasing a hand pose - Puppet Drag, the gizmo, or a Two-Bone IK key, plus the mirrored counterpart - captures a rig-space lock at that bone's tail, so the bones you moved by hand keep their points while the rest of the body swings free on the next drag. Re-posing a bone that already holds re-captures its anchor first, so a lock follows a deliberate edit instead of springing the bone back; these holds are marked `(held)` in the list, removed with the same X, and are session state that `rig.json` never records; a one-shot `timeline.grab` holds its bone and then re-solves the locks, like a mouse release. **Auto contact** makes the floor part of the same rule: the floor is the lowest rest tail of the contact bones (bones named foot / toe, or given an authored fixed plant), no drag can pull a tail below it, and a foot set down within 3% of the model height of it plants there - a session lock snapped to floor height, marked `(planted)` - while posing the foot's own limb (the foot and its single-child ancestors up to the hips, by drag, gizmo, pose bar or `timeline.pose`) so that the pre-solve foot rises above that tolerance releases the plant, and bringing it back down plants it again where it touched; a body or arm edit never changes contact, the leg bends to keep it. An authored rest plant is never rewritten by posing: it yields to the session with a `(lifted)` mark (ticking its box re-arms it), and a foot the user drags into the air is held there like any other bone. The contact point is the lower of the tail and the **heel** - a point carried by every bone named foot, under the ankle at the toe's rest height - so a foot posed toes-up plants on its heel (`(planted, heel)`; the two-bone solve aims the tail past the heel and re-aims up to three times as the foot turns, each pass kept only when the heel lands closer), a drag can push neither point through the floor (the target is lifted by what went through and the chain solved again, for the dragged foot and for any foot hanging under the dragged bone), and posing the foot itself - toes up, a turn - moves its plant to wherever it now touches, while posing the leg above it keeps the plant and bends the leg to it. Ticking a yielded rest plant back on drops the session plant that replaced it. Supports - for Balance and `timeline.balance` - are the locks planted on the floor, held or authored, so a hand put down on the floor counts and a hand held in the air does not; the Balance bake reads contact from the clip instead (see the Timeline paragraph). **Balance** (on by default, beside Hold Posed) is the cheap full-body prior: when a drag starts, the viewport records where the body's centre of mass (`BodyMasses`, the same proxy the Body bake uses) stands on the ground, and after every puppet solve it first counter-leans the trunk - the Location carrier when no foot hangs under it (the farmer's `body`; its legs hang from the control root), else the carrier's heaviest foot-free child (a mocap spine) - about its own base and away from the pull, by the angle that carries the upper body's mass back over the reference (`asin(e·M / (m_upper·h_upper))`), up to 15 degrees per drag and never when the trunk itself is the bone being dragged, and then shifts the bone that carries the body's Location - the shallowest bone with Location keys that is above every foot / toe bone or above none - a posed leg that happens to own Location keys carries a limb, not the body - so mocap hips under a keyless control root, else the skeleton root (`AnimationTimeline::LocationBone`, keyed through `KeyViewportPosition`, which follows the Move gizmo's Auto-Key rule and retweens like a user pose) - by whatever horizontal error is left, then re-solves the chain to its target and the planted-foot locks, up to eight rounds, so a hand pulled forward tips the body back and sends the hips after it instead of toppling the body while the hand stays under the cursor and the feet stay planted; dragging a bone whose lock is planted on the floor - an authored plant or a session plant - is a step, not a lean, and is not balanced - decided once when the drag begins, since the first drag frame lifts the plant - (the note says so, as does the tooltip), and typed pose-bar values, `timeline.pose` and the root's own Move gizmo are never balanced. The shift rides the drag's undo step. `timeline.balance` (enabled; returns the centre of mass, the support centre - the mean of the planted anchors - the carrier bone and its position, the lean bone and the last drag's lean in degrees) reads and toggles it. `timeline.grab`, `timeline.pin`, `timeline.lock`, `timeline.reference_load`, and `timeline.reference_clear` expose the tool; the matching legacy `rig.*` aliases open the combined window and select **Animate**, while the remaining `rig.*` actions select **Rig** and `rig.mode` maps `rig` / `edit` to **Rig** and `animate` / `pose` to **Animate**.
