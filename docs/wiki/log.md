# PhasmaEngine Wiki Log

## 2026-06-11

- Added a Script Editor function browser. `ScriptSystem::ListLuaFunctions()` walks the initialized Lua globals after all runtime/editor bindings register, filters out Lua stdlib noise, and returns entries like `engine.get_metrics()`; the Script Editor's `Show Functions` panel can refresh, filter, copy all, copy one function, or insert a selected function into the script buffer.

- Added opt-in per-material **night emissive**: `Material::nightEmissive` (Lua `material.set(h, "night_emissive", 1.0)`, serialized in material JSON and legacy factors `[1][1][3]`, GPU-side in `MaterialGpuData.attenuationColor.w` — layout unchanged). The opaque GBuffer flags such pixels by writing emissive alpha 0 (`GBufferPS.hlsl`), and the opaque lighting pass fades their emissive by direct-light luminance (`LightingPS.hlsl`), so emissive shows only where direct lighting is dim — city lights fade smoothly across a planet's terminator instead of glowing on the day side. Opaque-only by design; no instance override (the flag is a property of the material itself). Motivated by PhasmaSpace Earth night lights.

## 2026-06-10

- Fixed two runtime-UI input bugs that broke editor interaction with in-game UI. `InputState::SetMouse/KeyboardCapturedByUi` were OR-latches with no reset, so the first frame the runtime UI captured input permanently disabled Lua `input.*` polling — killing the `fly_camera.lua` editor fly camera until restart; hosts write complete capture state once per frame after event polling, so the setters are now plain assignments. Separately, stock `imgui_impl_sdl2` re-injects the raw window-relative mouse position from global mouse state on every NewFrame while no button is held, bypassing the runtime backend's Viewport-rect-to-surface event mapping; in the editor (Viewport offset + letterboxed) runtime-UI hover/clicks landed on the wrong widgets and produced spurious capture. The backend now queues the surface-mapped cursor position again after `ImGui_ImplSDL2_NewFrame` (`SyncMousePosition`), and pushes the cursor off-screen while frame input is disabled. Verified live: window→surface mapping is exact (probe quad hover at the mapped position) on the PhasmaSpace scene.

- Added `Primitives::CreatePolylineRibbon(points, width, normal, closed)` — a flat double-sided ribbon along a point path (orbit lines, paths, traces) — plus the `scene.attach_polyline(node, {vec3...}, width, normal, closed)` Lua binding. Geometry expands across the given plane normal and emits both windings so it reads from either side. Note: polyline meshes do not round-trip through `.pescene` primitive params (points are not serialized) — creators should rebuild them at load time, as the PhasmaSpace director does.

- Added opt-in physically based point-light attenuation. New `GlobalSettings::physical_point_falloff` (default off, Lua `settings.set("physical_point_falloff", ...)`, Global widget "Physical Falloff" checkbox, serialized in `.pescene`) switches `ComputePointLight` in `Lighting.hlsl` from the range-relative `(1 - (d/r)^2)^2` falloff to windowed inverse-square (`window / d^2`), where intensity is interpreted as luminance × distance². Plumbed through the spare `LightPassUBO` pad slot, so the UBO layout is unchanged. Raster lighting path only for now — `RT_ComputePointLight` in `RayTrace.hlsl` keeps its own legacy falloff, so Hybrid/RT direct lighting ignores the flag. Motivated by the PhasmaSpace solar-system demo (real inverse-square sunlight: Mercury overexposes, Neptune nearly dark at Earth-anchored intensity).

A per-texel Cranley-Patterson jitter was tried and removed — once the mip bias converged the integral it only traded the grid for swimming grain. The prefilter stays a one-time bake at skybox load, not per frame. Verified in the editor on `golden_gate_hills_4k.hdr`.
