## Source-verified constraints

- `Depth/DepthVS.hlsl` and `Gbuffer/GBufferVS.hlsl` evaluate current clip position with the same `precise` expression, `P * ((J * M) * VP)`. Reassociating this expression previously broke the G-buffer EQUAL depth test, especially on DX12. Both raster consumers must read the same precomputed current clip value.
- `GBufferVS.hlsl` uses the previous joint palette, previous world matrix and previous view projection for velocity. A static current pose must settle to zero velocity; changing bones with a stationary node must still produce velocity.
- Normals/tangents use `remove_scale3x3(J * M)` per vertex before interpolation. Separately normalizing a skinned normal and then applying a normalized world matrix is not equivalent under nonuniform scale.
- Visibility stores draw ID and three global source vertex indices. Geometry may be shared by instances with different poses. Deformed addressing must include the draw/instance and source vertex range; one result per global source index is incorrect.
- `VisibilityCommon.slang` reconstructs rigid source vertices today. Debug, thin and shade consumers must share the deformation-aware reconstruction.
- `SceneNode.cpp` updates both full and depth-only vertex stores for sprites. Its transfer barrier currently targets vertex input; compute readers need an explicit dependency. Sprite UV/next-UV/blend data must survive reconstruction.
- `VisibilityPS.hlsl` and `DepthPS.hlsl` currently use legacy base-alpha and alpha-cut. Generated masks must also agree with every later depth-equal consumer and shadow coverage; merely changing one visibility pixel shader is incomplete.
- Existing scripted `primitives.skinned_strip_2d` and `animation.set_joint_rotations_z` provide fixed poses without test-only engine hooks. The planar strip alone does not validate out-of-plane normals: add a small independent 3D skin fixture before accepting the complete skinning slice.
- Native strip prefab instances deliberately copy mutable geometry (`SceneSerializer.cpp`, `mutablePrefabGeometry`). The 100-strip performance workload therefore measures independent copies. Shared-range correctness uses cooked weighted skins and asserts identical source offsets before testing opposite joint poses.

### 4.2 — sprites

Reuse the dynamic geometry already produced by the sprite system. Make visibility and graph evaluation honor current UV, next UV, frame blend, flip, dimensions and vertex color. Determine the smallest correct implementation from the existing sprite contract; avoid computing deformation a second time if the CPU has already supplied it. Gate a generated two-frame atlas at frame endpoints and intermediate blend, flip/resize, textured graph, legacy fallback, overlap and history on both APIs.

Design decision (source checked 2026-10-17): evaluate the upstream graph at both frame UVs, interpolate the evaluated OpenPBR surface inputs, then shade once. Thin values derive from those same inputs (including multiplying blended base color by blended base weight). Interpolate normal directions with normalization and a defined degenerate fallback. A final-lighting crossfade would disagree with the thin G-buffer and change the existing material-interpolation behavior. Reuse the outer surface-call boundary already found by `CaptureThinInputs` in `MaterialXGen.cpp`; the internal PE light-loop override is too late. The texture helper cannot apply a raw atlas-UV delta after arbitrary graph UV transforms or blend encoded color samples correctly.

This justifies adding first-party `MaterialXGen.cpp` and `OpenPBRMaterial.cpp/.h` to the sprite scope. Generated-module ABI must be versioned and included in the existing cooked-cache key: the present key tracks document contents/context, not generator changes. Regenerate editor caches and explicitly reject incompatible cooked-only modules with regeneration/re-export guidance. Retain existing zero-blend generated entry points for standalone codegen callers. Do not edit third-party code or add a custom shader generator. A Claude design consultation was attempted but unavailable because its OAuth session had expired; the decision above is based on direct source review.

### 4.3 — generated alpha-cut mask

Generate an opacity-only raster entry from the selected MaterialX surface. Integrate graph-specific raster coverage with both Hi-Z phases and the depth-equal G-buffer; reconcile shadows and sprite blending explicitly. Preserve opaque/legacy/unsupported/alpha-blend behavior. Accepted routing (source reviewed 2026-10-18; runtime acceptance pending): the existing culled alpha-cut lists could be replayed per active mask graph, rejecting other modules per instance in the vertex stage. Instance batches may mix materials, so command-level filtering alone is incorrect. This avoids compute binning but repeats vertex work as module count grows; measure that cost and use dirty-built module-specific fixed command slots if replay fails the performance gate. Both early/late depth need identical masks before Hi-Z construction. Enrolled G-buffer draws must bypass the later legacy-alpha discard and rely on EQUAL coverage. Regular shadow pipelines are currently vertex-only, so generated cutouts need a masked route and exclusion from the ordinary route. Skinning moves from priority 190 to 90, before shadows at 100, with the render-graph dependency declared. Shadow surface attributes must be interpolated from that geometry, not reconstructed from the main-camera visibility image. Gather active mask modules per mesh before the shared material byte-offset early exit. The implementation follows these constraints; runtime and performance gates remain required.
