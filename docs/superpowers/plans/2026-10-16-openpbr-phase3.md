# OpenPBR Phase 3: graphs, textures, import, persistence

Date: 2026-10-16. Follows [Phases 0-2](2026-10-13-openpbr-materialx-phase0-2.md) and [parity (2.5)](2026-10-15-openpbr-parity.md); spec: [OpenPBR design](../specs/2026-10-13-openpbr-design.md), Phase 3 = "Textures, `.mtlx` import, glTF → MaterialX conversion, persistence, Lua/editor (all 41 inputs), per-graph pipelines, binning at scale, the bindless cap".

## Contract (unchanged from 2.5)

Every graph PE renders matches MaterialX 1.39.5's own `GlslRenderer` on the same document, same mesh, same camera, same light or environment (equal FIS sample count): direct light ≤ 2/255 encoded on the parity sphere and plane (same exceptions as 2.5: anisotropy on the tangent-less sphere, grazing rim), environment within `openpbr_parity.py` `ENV_TOLERANCE`. PE's lights, shadows, GI, reflections and tone mapping stay engine-specific and are off in parity runs.

## Source facts this plan builds on (verified 2026-10-16)

- The depth prepass writes the visibility payload (`VisibilityPS.hlsl:37`; terrain and voxels clear it where they win depth). The raster G-buffer still rasterises MaterialX meshes with their legacy data and leaves visibility untouched (write mask off, `GbufferPass.cpp:49, 168`); pass 1 (`MaterialThin.slang`) overwrites normal, albedo and srm for `editorFlags & 32` pixels and clears emissive (pass 2's colour includes emission). If pass 1 skips a pixel, the legacy mirror values stay in the G-buffer.
- `MaterialXGen.cpp:335-383` emits `pe_material_thin` only when `base_color`, `base_weight`, `specular_roughness`, `base_metalness` are uniforms and `geometry_normal` is unconnected; otherwise there is no helper and `MaterialThin.slang` cannot compile against the module.
- The generated module calls the surface as one compound function, `NG_open_pbr_surface_surfaceshader(<arg per input>, …, <surface>_out)` inside `pe_material_fragment` (generated `PeOpenPBRDefault.slang:2298-2310`); the arguments are uniform names or upstream local outputs.
- Only `PeOpenPBRDefault` exists: CMake runs `PhasmaCook --mtlx <file.mtlx> <outDir>` (`Phasma/Cook/CMakeLists.txt:89-101`, outputs named by material name), and both passes hard-include `Generated/PeOpenPBRDefault.slang` (`MaterialShade.slang:29`, `MaterialThin.slang:89`). `GetOpenPBRDefaultLayout()` pins 37 inputs / 220 bytes / thin; `OpenPBREligible` (`OpenPBRMaterial.cpp:176`) and the pass enables (`SceneRenderGraph.cpp:547-549, 602-604`) test `GetOpenPBRDefaultLayout().valid`; `MeshUsesOpenPBR` sites: `SceneBuffers.cpp:152, 933, 1219, 2366`.
- PhasmaCook is installed next to the editor with MaterialX's library data (`cmake/PhasmaRuntimeLayout.cmake:161-167`). `Base/Process.h` `RunProcess` (used for slangc, `SlangCompiler.cpp:505`) runs a tool with a timeout.
- Shader cache: `ShaderCache::ParseShader` expands quoted includes itself (relative to the including file, then the engine-counterpart fallback) and hashes the expanded text; slangc compiles that expanded text from a temp file (`VulkanShaderImpl.cpp:232`, `Dx12ShaderImpl.cpp:596`, `SlangCompiler.cpp:418-465`). A generated file outside `RuntimeAssets` compiles if its includes resolve through `ParseShader`.
- Material record: 80-byte legacy `MaterialGpuData`, inputs at `+80` (`PE_OPENPBR_INPUTS_OFFSET`). `transmissionVolume.w` (byte `+60`) has no reader: no shader, no `standard_pbr.pass` mapping (`.xyz` only), RT reads its own table (`RayTrace.hlsl:173`), persistence writes legacy fields, not this record (`SceneSerializer.cpp:1864`, `ModelAssetCooked.cpp:505`); `attenuationColor.w` is `nightEmissive`, in use. OpenPBR records skip the `standard_pbr` packing: `SceneBuffers.cpp:933` → `BuildOpenPBRBytes` (`:994`), which copies `BuildGpuData()` (`Material.cpp:516` zeroes `.w`). Full rebuilds size the buffer from the accumulated records (`SceneBuffers.cpp:1028`); dirty updates rewrite bytes at the existing offset without a size check (`:1227`, `:1265`).
- Module-pinned code beyond the loader: `MirrorOpenPBRToLegacy` (`OpenPBRMaterial.cpp:264`) and `set_openpbr`/`get_openpbr` (`MaterialBindings.cpp:535, 579`) resolve names through the default layout; `ResolveOpenPBRInput` (`OpenPBRMaterial.cpp:193`) knows `float[3]` and turns integers into booleans; the runtime keeps only the leaf input name (`:136`) although the cooker emits `node` + `input`. The cooker can emit integer, float2/4 and matrix uniforms (`MaterialXGen.cpp:29`); `MaterialParamValue` has no matrix (`Material.h:38`).
- Pass lifetime: passes initialise once (`SceneRenderGraph.cpp:346`); thin rebuilds only on output-format changes (`MaterialThinPass.cpp:132`), shade only on define changes (`LightPass.cpp:1093`). `GetPassInfos` exposes one pipeline per pass (`Component.h:52`); shader reload snapshots those pointers (`RenderPassShaderReload.cpp:140`).
- `OpenPBREligible` checks only the pass file and the default layout (`OpenPBRMaterial.cpp:177`): today nothing keeps masked or blended meshes out. Pass 1's `pe_view_position()` returns zero (`MaterialThin.slang:41`).
- Textures: the legacy G-buffer binds `scene.GetImageViews()` (`GbufferPass.cpp:316-323`) with one default sampler; slots 0 (base colour) and 4 (emissive) index sRGB views in `linear_color` scenes (`SceneBuffers.cpp:19-23`). One unbounded array per descriptor set, as its last binding (`Descriptor.cpp:234-243`); cap `PE_MAX_DESCRIPTORS_PER_BINDING` = 500 (`RHITypes.h:10`). Today `pe_textures[]` + `pe_samplers[]` are declared (MaterialShade set 2 b1/b2, MaterialThin set 1 b0/b1) but never bound, and as declared they break that rule. `mx_texture.slang` (PE override) samples `pe_textures[textureIndex]` with `pe_samplers[samplerIndex]`.
- MaterialX ships glTF nodes in `libraries/bxdf/gltf_pbr.mtlx`: `gltf_colorimage`, `gltf_image` (color3/color4/float/vector3), `gltf_normalmap`, `gltf_iridescence_thickness`, `gltf_anisotropy_image`.
- Persistence: `Resolve()` and the undo snapshot drop `m_paramOverrides` and `m_openpbr`; `MaterialBindings.cpp:504-505` "Not saved with the scene until Phase 3". glTF import (`ModelAssetAssimp.cpp`) reads 5 texture slots and basic scalars only; `.pemesh` v8, `MaterialScalarRecord` 85 bytes.

## Decisions

1. **Code is shared, values are not.** A *module* (code, byte layout, pipelines) is identified by a hash of its generated `.slang` text, not by material name (two documents may both name their material `Material`). A *material source* (`.mtlx` path + material name) points at a module and keeps its own defaults from its own `.json`: two documents with the same code and different constants share pipelines and render their own values. Structurally identical graphs dedup only if their node names match, because `SHADER_INTERFACE_COMPLETE` names uniforms after nodes: generators PE writes (glTF import, 3.4) emit canonical node names. Every input is identified by node path + input name (`node.input` in Lua); the bare OpenPBR input name stays an alias for the surface node's own inputs.
2. **Live generation runs `PhasmaCook --mtlx` as a subprocess** (`RunProcess`, into a temp dir, then renamed by hash into `<Root>/ShaderCache/MaterialX/`). *Spec amendment, confirmed by the user 2026-10-16:* the spec said the editor links MaterialX; the subprocess reuses the installed tool, keeps live import and export on one generator, keeps MaterialX out of the editor and the hot-reload module, and turns a malformed document into an error instead of an editor crash. Revisit only for an in-editor node graph that regenerates on every connection change. The Player never generates: it loads modules cooked at export (3.3).
3. **Per-module pipelines through wrapper sources.** Each pass is split at the module include into a head and a main file; the registry writes `<hash>.thin.slang` / `<hash>.shade.slang` wrappers that include head, module and main by literal absolute paths (forward slashes), which `ParseShader` resolves as written. Each pass keeps one pipeline per module in use, reconciled with the scene's modules every frame (first assignment, replacement, removal, scene switch); a module renders only once its pipelines exist. `GetPassInfos` returns all of them and shader reload keeps working (`PassInfo` identity preserved across a reload). Known limit, as today: hot reload watches the wrapper, not the files it includes.
4. **Module index in the material record:** byte `+60` (`MaterialGpuData.transmissionVolume.w`) holds the module's runtime registry index as a raw `uint`, stamped inside `BuildOpenPBRBytes` after it copies the 80-byte prefix, so every full and dirty upload carries it. Runtime-only: never serialised. Pixels whose draw belongs to another module return early. Full-screen dispatch per module until binning (3.6). **Changing a mesh's module (or layout) forces a full material-byte repack and mesh-constant offset rebuild before the next render; dirty updates only rewrite a record whose size and layout are unchanged.**
5. **Pass 1 evaluates the graph.** Every module gets the same pass-1 helper: the generator inserts captures into `pe_` statics immediately before the `NG_open_pbr_surface_surfaceshader` call (the argument expressions for `base_color`, `base_weight`, `specular_roughness`, `base_metalness`, `geometry_normal`, taken from MaterialX's `ShaderGraph`, not by regex on the call), and `pe_material_thin` calls `pe_fill_vertex_data(sp)` then `pe_material_fragment` and returns the captures. Only the *lighting* hooks are stubs in pass 1 (0 lights, 0 environment samples, no traced reflections); graph inputs are real (`pe_view_position()` returns the camera, so a `viewdirection` node evaluates as in pass 2). The `thin:false` path is deleted. Graphs whose evaluation has side effects pass 1 cannot drop (`discard` from transparency) are rejected with a clear error until Phase 4. *Amended 2026-10-16 (as built):* dead-code removal alone left 8 Airy-Fresnel closure loops in pass 1 (Sol's SPIR-V count, 64 in pass 2), so the generator now cuts the fragment after the captures: `#ifdef PE_MATERIAL_THIN` returns there, `#else` keeps the surface call (MaterialX emits nodes in topological order, so everything the captures need comes first), and only `MaterialThinHead.slang` defines it. Pass 1 then contains no closure code by construction; the check is the pass-1 `OpLoopMerge` count plus the paired timing.
6. **Textures in their own descriptor set** where one is free (pass 1: set 1; pass 2 uses all four spaces, so there the array is set 2's last binding), the unbounded `pe_textures[]` as its set's last binding; samplers as a small fixed array in another binding/set (no unbounded sampler array). MaterialX textures bind **raw (UNORM) views**; colour-space conversion is MaterialX's (`colorspace="srgb_texture"` on the image node with `targetColorSpaceOverride = lin_rec709`), so nothing decodes twice in either `linear_color` mode.
7. **AO and alpha.** OpenPBR has no occlusion input: an imported occlusion map (3.4) multiplies PE's environment terms like `pe_ssao`, outside the graph; parity runs have none. *New requirement in 3.1a:* `MeshUsesOpenPBR` also requires the mesh's effective render type to be opaque or alpha-cut (alpha-cut keeps the legacy alpha test in `VisibilityPS` until Phase 4's `Mask()`); blended meshes stay legacy until Phase 6. The same predicate drives enrolment, byte packing, dirty updates and `editorFlags`.
8. **Legacy mirrors** (spec "Legacy fallback") are written from each mesh's own module and values (`MirrorOpenPBRToLegacy` made module-aware): Android, the off switch and RT hits keep rendering a material through its mirrored constants. A connected input has no constant: its legacy field keeps the material's own value.
9. **Input types:** bool, integer (stays an integer), float, float2, float3 (color3/vector3), float4 are parsed, resolved, stored and packed exactly; matrix and string inputs are rejected with a clear error until a graph needs them. The layout validation the default has today (type widths, default counts, alignment, non-overlap, overflow-safe bounds) applies to every module.

#### 3.3a Scene persistence (Sol, xhigh)

- One helper pair writes and applies a mesh's OpenPBR state as one JSON object, `"openpbr": {"mtlx": <project-relative path>, "material": <name>, "inputs": {<node.input>: value}}` (`mtlx` absent = the default module; only overrides that differ from the source's own values are written), called by `AddMeshes` and all five readers; `Resolve()` stays legacy-only. Undo, play/stop and hot reload follow from the JSON. Applying a source on load generates or reuses its module as `use_mtlx` does.
- The shared-mesh bug is fixed at the loader: a saved mesh whose scene mesh is already claimed by an earlier saved mesh gets its own mesh entry over the same geometry, so every object keeps its own material (legacy and OpenPBR).
- **Gate (Claude):** the 3.1a gate graph and the default module on two spheres plus a textured plane, with Lua overrides; save, new scene, load: each object matches its pre-save capture (both APIs); an override edit then `edit.undo` restores the image; play then stop keeps the graphs.
- *As built 2026-10-16:* Sol wrote `WriteOpenPBR`/`ApplyOpenPBR` and `ClaimMesh` (a second saved mesh on a claimed source mesh gets its own Mesh over the same geometry, its own Material copy, BLAS aliased), then stopped: script/MCP edits never arm the editor's undo capture (`GUI::NotifyChange` is called by UI widgets only), so `edit.undo` had nothing to undo.
